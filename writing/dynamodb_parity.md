# DynamoDB compatibility matrix

Last updated: 2026-11-14

Legend: ✅ supported | 🟡 partial or different | ❌ unsupported

## Overall status

| Area                                       | Status | Unsupported / differences                                                                                                          |
| ------------------------------------------ | ------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| DynamoDB JSON HTTP endpoint                | ✅     |                                                                                                                                    |
| AWS SDK-style request bodies               | ✅     |                                                                                                                                    |
| SQLite backend                             | ✅     |                                                                                                                                    |
| Turso backend                       | ✅     |                                                                                                                                    |
| Postgres backend                           | ✅     |                                                                                                                                    |
| RocksDB backend                            | ✅     |                                                                                                                                    |
| FoundationDB backend                       | ✅     |                                                                                                                                    |
| Remote provider mode                       | ✅     |                                                                                                                                    |
| `CreateTable`                              | 🟡     | Response shape (`CREATING`, GSIs `CREATING` without `Backfilling`, GSI `IndexArn`/size/count) and attribute definitions in name order match AWS (probe P13 in [ddb-parity-aws-probe-2026-11-13.log](../docs/plans/incomplete/handover/ddb-parity-aws-probe-2026-11-13.log)). Capacity is intentionally unsupported: `BillingMode` and `ProvisionedThroughput` are accepted and ignored, and every table reports the fixed on-demand `BillingModeSummary` with no throughput. LSIs are validated, not created; resource policy, SSE/KMS, tags, table class, `OnDemandThroughput` and `WarmThroughput` are not provided. `TableArn` uses a fixed `us-east-1:123456789012`. |
| `ListTables`                               | ✅     |                                                                                                                                    |
| `DescribeTable`                            | 🟡     | GSI `IndexArn`/size/count, `Backfilling` only while an index is not `ACTIVE`, and `UPDATING` while a GSI builds match AWS (probe P13). Capacity is intentionally unsupported: no `ProvisionedThroughput` and no `LastUpdateToPayPerRequestDateTime`. `WarmThroughput` and `TableClassSummary` are absent; `TableSizeBytes`, `ItemCount` and GSI sizes are 0; `LatestStreamLabel` is the ISO timestamp of the stream enable (the table creation for a stream created with the table), as in AWS (P13 DeleteTable probe); each enable, including a re-enable after a disable or a recreated table name, gets a new label and ARN, and the store moves a stamp that another enable already used (same millisecond, or a node clock behind) forward by 1 ms; `MaxIndexers` is an aux extension. |
| `DeleteTable`                              | 🟡     | The response is `DELETING` and leaves out `AttributeDefinitions`, `KeySchema` and `CreationDateTime`, as the AWS description does (P13 DeleteTable in the [probe log](../docs/plans/incomplete/handover/ddb-parity-aws-probe-2026-11-13.log)). Capacity is intentionally unsupported (no `ProvisionedThroughput`). The probe table had no GSI, so GSI entries in the response are unverified; `MaxIndexers` is an aux extension. |
| `UpdateTable`                              | 🟡     | `UPDATING` with the new GSI `CREATING` and `Backfilling: false` for a GSI create, the stream re-enable text, a view-type change after a disable (accepted) and the CREATING-GSI Query text match AWS (probe P13). A stream enable after a disable starts a new, empty stream with a new label and ARN, as on AWS; records of the earlier enable are retired and are not served under the new ARN or view. Unlike AWS, the earlier stream is not readable for 24 hours under its old ARN: requests with that ARN or its iterators return `ResourceNotFoundException`. A deleted GSI is shown `DELETING` in the response with the table `UPDATING` (the probe log has no GSI-delete case; this is the AWS-documented behaviour) and is gone in DescribeTable. Capacity is intentionally unsupported: `BillingMode`, `ProvisionedThroughput` and GSI throughput updates are accepted and ignored. Changes apply synchronously, so DescribeTable is `ACTIVE` once a GSI build finishes. SSE/KMS, table class and non-GSI attribute definition changes are not provided. A deleted GSI's `AttributeDefinitions` entries are kept after the delete (recorded AWS ddbpar5b: DescribeTable right after delete still lists them); AWS prunes them once the index is gone, and aux has no completion step (🟡 deferred). |
| `PutItem`                                  | 🟡     | Legacy `Expected` and `ConditionalOperator` are rejected, not applied (AWS texts for mixed or lone use, probe P11 in [ddb-parity-aws-probe-2026-11-13.log](../docs/plans/incomplete/handover/ddb-parity-aws-probe-2026-11-13.log)); item collection metrics differ; consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `GetItem`                                  | 🟡     | Consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `DeleteItem`                               | 🟡     | Legacy `Expected` and `ConditionalOperator` are rejected, not applied; item collection metrics differ; consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `UpdateItem`                               | 🟡     | Legacy `AttributeUpdates`, `Expected` and `ConditionalOperator` are rejected, not applied (mixed with an expression: AWS text, probe P11); item collection metrics differ; consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `Query`                                    | 🟡     | Deliberate difference: a 1 MB page stops before the item that would cross 1 MB (AWS includes it), so each non-final page is the maximal prefix within 1 MB. Legacy `KeyConditions`, `QueryFilter` and `ConditionalOperator` are rejected, not applied (mixed with an expression: AWS text, probe P11); `AttributesToGet` is supported. Consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `Scan`                                     | 🟡     | Deliberate difference: a 1 MB page stops before the item that would cross 1 MB (AWS includes it). Legacy `ScanFilter` and `ConditionalOperator` are rejected (AWS applies `ScanFilter` alone; mixed with `FilterExpression` the AWS text, probe P11); `AttributesToGet` is supported. Consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `BatchWriteItem`                           | 🟡     | AWS throttling and item-collection metrics differ; consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `BatchGetItem`                             | ✅     | Consumed capacity is returned with zero values when requested (intentionally unsupported). An unknown table returns the bare `Requested resource not found`, as AWS does. |
| `TransactWriteItems`                       | 🟡     | Item-collection metrics differ; consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `TransactGetItems`                         | 🟡     | Items totalling more than 4 MB return `ValidationException` `Payload in response is too large.` and no items. Consumed capacity is returned with zero values when requested (intentionally unsupported). |
| `UpdateTimeToLive`                         | ✅     |                                                                                                                                    |
| `DescribeTimeToLive`                       | ✅     |                                                                                                                                    |
| `GetStreamRecords`                         | 🟡     | Simplified API. Not full DynamoDB Streams compatibility. An invalid `ShardIterator` returns `ValidationException`: `Invalid ShardIterator`. |
| Global secondary indexes                   | ✅     | Eventually consistent reads; creation backfills existing items while writes continue. A backfill skips items whose index key attribute has the wrong type, on every provider. |
| Local secondary indexes                    | ❌     | Real LSI semantics are not implemented.                                                                                            |
| Condition expressions                      | ✅     | Syntax errors, empty expressions, literal operands and function arity return the AWS texts (`Syntax error; token: ..., near: ...`, probes P1–P10 in [ddb-parity-aws-probe-2026-11-13.log](../docs/plans/incomplete/handover/ddb-parity-aws-probe-2026-11-13.log)). |
| Update expressions                         | ✅     | Syntax errors, empty expressions, literal operands and function arity return the AWS texts (`Syntax error; token: ..., near: ...`, probes P1–P10 in [ddb-parity-aws-probe-2026-11-13.log](../docs/plans/incomplete/handover/ddb-parity-aws-probe-2026-11-13.log)). |
| Key-condition expressions                  | ✅     | Syntax errors, empty expressions, literal operands and function arity return the AWS texts (`Syntax error; token: ..., near: ...`, probes P1–P10 in [ddb-parity-aws-probe-2026-11-13.log](../docs/plans/incomplete/handover/ddb-parity-aws-probe-2026-11-13.log)). |
| Filter expressions                         | ✅     | Matches AWS as probed on 2026-11-13 ([gsi-filter-aws-probe.md](../docs/plans/incomplete/handover/gsi-filter-aws-probe.md)). On a `KEYS_ONLY` or `INCLUDE` GSI, a `Query` `FilterExpression` that names (at any path depth) an unprojected attribute returns `ValidationException` (`One or more parameter values were invalid: Secondary index <name> does not project one or more filter attributes: [...]`) before the read; a `Scan` accepts it and evaluates the filter against the projected index item, so the attribute is missing (`a = :v` matches nothing, `attribute_not_exists(a)` matches, `ScannedCount` counts index items). A GSI `ProjectionExpression` or `AttributesToGet` naming an unprojected attribute returns `Global secondary index <name> does not project [...]`, and `Select: ALL_ATTRIBUTES` returns `Select type ALL_ATTRIBUTES is not supported for global secondary index <name> because its projection type is not ALL` (Query probed; Scan uses the same check). Table and index key attributes count as projected; `ALL` indexes are not checked ([projection_expression.rs](../crates/storage-types/src/projection_expression.rs), [dynamo_range_read.rs:465](../crates/storage-provider/src/dynamo_range_read.rs#L465)). A `Query` `FilterExpression` that names a key attribute is rejected. |
| Projection expressions                     | ✅     | Syntax errors, empty expressions, literal operands and function arity return the AWS texts (`Syntax error; token: ..., near: ...`, probes P1–P10 in [ddb-parity-aws-probe-2026-11-13.log](../docs/plans/incomplete/handover/ddb-parity-aws-probe-2026-11-13.log)). |
| Number attribute values | ✅ | Stored and returned in canonical spelling (`1e3` is returned as `1000`; zero is `"0"`). A zero with an out-of-range exponent (`0E126`, `0E-131`) is rejected, and `1E<huge>` reports overflow. A malformed number returns `ValidationException` echoing the value (`...numeric value: abc`); an empty number keeps the bare message. |
| Unknown-table errors | ✅ | Data-plane item operations (`PutItem`, `GetItem`, `UpdateItem`, `DeleteItem`, `Query`, `Scan`, `BatchGetItem`, `BatchWriteItem`, `TransactGetItems`) on a missing table return bare `Requested resource not found`; control-plane operations return `Requested resource not found: Table: X not found`. |
| Strongly consistent reads                  | ✅     | Base-table reads only; strongly consistent GSI reads are rejected.                                                                                              |
| Pagination markers                         | ✅     | Query that evaluates exactly its `Limit` returns `LastEvaluatedKey`; the next page may be empty. |
| Table streams                              | 🟡     | Not the AWS DynamoDB Streams API. Each enable is its own stream (label, ARN, records); a disabled stream is not readable afterwards (AWS keeps it for 24 hours). |
| TTL expiry behavior                        | ✅     |                                                                                                                                    |
| Consumed capacity reporting                | 🟡     | Returned with zero values when requested (intentionally unsupported): no capacity accounting runs. |
| Item collection metrics                    | 🟡     | Complete AWS item-collection metrics are not implemented.                                                                          |
| Provisioned/on-demand capacity enforcement | ❌     | Intentionally unsupported (owner decision, not a gap): billing mode and throughput are accepted and ignored, never stored, echoed or enforced. |
| PartiQL                                    | ❌     | `ExecuteStatement` and `BatchExecuteStatement` are not implemented.                                                                |
| Continuous backups / PITR                  | ❌     | `UpdateContinuousBackups` returns an unsupported validation error. Backups and PITR available via backend provider.                |
| Export/import APIs                         | ❌     | DynamoDB export/import control-plane APIs are not implemented.                                                                     |
| IAM / SigV4 / account isolation            | ❌     | Auth and account-management services are outside the compatibility surface.                                                        |
| KMS / SSE management                       | ❌     | AWS KMS/SSE behavior is not implemented.                                                                                           |
| Tags as AWS resource management            | ❌     | AWS resource tagging behavior is not implemented.                                                                                  |
| CloudWatch / AWS service events            | 🟡     | CloudWatch metrics and AWS service events are not implemented. Uses prometheus /metrics endpoint                                   |
| Global tables                              | 🟡     | Two regions; `ReplicaUpdates` Create/Delete; eventual consistency only (no MRSC); table settings are per region |

## Gaps

| Gap | Aux behavior | AWS behavior | Proposed fix |
| --- | ------------ | ------------ | ------------ |
| Query `ProjectionExpression` on an attribute an LSI does not project | LSIs are not implemented (see Local secondary indexes); the index is not found. | Fetches the attribute from the base table and returns it ([gsi-filter-aws-probe.md](../docs/plans/incomplete/handover/gsi-filter-aws-probe.md)). Query and Scan filters on an LSI behave as on a GSI. | Part of real LSI support. |
| `UpdateTable` delete of a GSI that is still `CREATING` | Rejected with `LimitExceededException` until the build finishes. | Accepted (the build is cancelled). | Cancel a running backfill. |
| `DeleteTable` while a GSI is `CREATING` | Accepted. | `ResourceInUseException`: `Cannot delete table while indexes are being created, updated, or deleted.` | Refuse the delete; needs a `ResourceInUseException` carrying a message. |
| `UpdateTimeToLive` disable soon after an enable | Accepted. | `ValidationException`: `Time to live has been modified multiple times within a fixed interval`. | Track the last TTL change time. |
| Stream ARN of a disabled stream | The stream is not readable (see Table streams). `DescribeTable` drops `StreamSpecification` and `LatestStreamArn` once the stream is off. | `LatestStreamArn` keeps naming the disabled stream. | Keep disabled streams readable. |
