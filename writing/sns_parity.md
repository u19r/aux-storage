# SNS compatibility matrix

Last updated: 2026-11-13

Legend: ✅ supported | 🟡 partial or different | ❌ unsupported

Method: this matrix was written by reading the code, not by running it. It describes the working tree on the
date above. No row claims live AWS verification. The repository holds fixtures that state they were captured
from AWS on 2026-05-05 ([pubsub/tests/fixtures/aws](../crates/pubsub/tests/fixtures/aws/)): seven error cases,
the HTTPS notification, the raw and enveloped SQS notification, and the HTTPS confirmation message. Those
fixtures are cited as "AWS fixture in the repository"; this assessment did not repeat the capture. Everything
else is "from AWS documentation, not probed". There is no SNS equivalent of `docs/sqs-error-parity.md`.
Where a note says "not verified", the code was read but the AWS behaviour or the Aux behaviour was not exercised.

Source map: wire decoding and rendering in [pubsub/src/protocol.rs](../crates/pubsub/src/protocol.rs), manager in
[pubsub/src/manager.rs](../crates/pubsub/src/manager.rs), delivery in
[pubsub/src/delivery_transport.rs](../crates/pubsub/src/delivery_transport.rs), notification bodies in
[pubsub/src/notification.rs](../crates/pubsub/src/notification.rs), domain rules in
[pubsub-provider/src](../crates/pubsub-provider/src/), HTTP route in
[storage-api/src/routes/pubsub/mod.rs](../crates/storage-api/src/routes/pubsub/mod.rs).

## Request parameter handling

The decoder reads the parameters it knows from the form body and ignores the rest
([protocol.rs:124](../crates/pubsub/src/protocol.rs#L124)). An AWS parameter that is not listed in the tables below is
silently dropped, with the exceptions called out as "Rejected". A missing required parameter is reported as
`InvalidParameter` with the text `Invalid parameter: AttributeName` whatever the parameter is
([protocol.rs:316](../crates/pubsub/src/protocol.rs#L316)). Attributes are read from the indexed
`Attributes.entry.N.key` / `.value` form; `SetTopicAttributes` and `SetSubscriptionAttributes` read the single
pair `AttributeName` / `AttributeValue`.

### CreateTopic

| Parameter              | Handling | Validation / default                                                                                                                                                        |
| ---------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Name`                 | Accepted | 1 to 256 characters of ASCII letters, digits, `-`, `_`. `.fifo` suffix rejected. Error `InvalidParameter`, `Invalid parameter: Topic Name` (AWS fixture in the repository). |
| `Attributes.entry.N`   | Accepted | `DisplayName`; `FifoTopic=false`. Anything else is rejected ([topic_attributes.rs](../crates/pubsub-provider/src/topic_attributes.rs)).                                     |
| `Tags.member.N`        | Accepted | Stored on the topic; returned by `ListTagsForResource`.                                                                                                                     |
| `DataProtectionPolicy` | Ignored  | Not decoded.                                                                                                                                                                |
| Same name again        | Accepted | Returns the existing ARN. Attributes are not compared; AWS rejects different attributes (from AWS documentation, not probed).                                               |

ARN: `arn:<queue.partition>:sns:<queue.region>:<queue.account_id>:<name>`, defaults `aws`, `us-east-1`, `000000000000` (note 1). An application that builds the ARN from its own region and
account gets `NotFound` because lookup is by exact ARN string.

Settable by `SetTopicAttributes`. |

### Subscription attributes

| Attribute                                                                             | Handling      | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

| `RawMessageDelivery`                                                                  | Read, write   | `true` or `false` (any case); another value is `InvalidParameter`. Effective for `sqs` and for the dead-letter message form.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `TopicArn`, `SubscriptionArn`, `Protocol`, `Endpoint`, `Owner`, `PendingConfirmation` | Read          | `Owner` is the account of the topic ARN.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `FilterPolicy`, `FilterPolicyScope`                                                   | Read, write   | Evaluated when a publication is materialized; a subscription that does not match gets no delivery record. Operators: exact strings and numbers, `prefix`, `suffix`, `equals-ignore-case`, `wildcard`, `cidr` (IPv4 and IPv6), `numeric` with one or two bounds, `exists`, `anything-but` (strings, numbers, `prefix`, `suffix`, `wildcard`, `equals-ignore-case`), `prefix` with `equals-ignore-case`, the literals `null`, `true`, `false`, and `$or`. Limits: 5 keys ("Filter policy can not have more than 5 keys") and 150 combinations ("Filter policy is too complex"), as AWS; 256 KiB (not probed). Semantics from the AWS probe: a message with no attributes matches no attribute policy, not even `exists: false`; `exists: true` does not match a Binary attribute; `anything-but` does not match an absent key; a numeric condition does not match a String attribute; `String.Array` matches when one element matches. A stored policy that cannot be parsed lets every message through. Errors for an unknown match type, a bad numeric operator, an unsupported `anything-but` pattern, a non-boolean `exists` and a key whose value is neither an object nor an array end with the Jackson location, `<message>\n at [Source: (String)"<policy without whitespace>"; line: 1, column: <n>]` (AWS behavioural suite). `FilterPolicyScope` other than the two values is `Invalid value [<value>]. Please use either MessageBody or MessageAttributes`. A nested policy under `MessageAttributes` scope is accepted (probe A3; the suite expects a refusal, see the conflict list). Not probed: the matching of a nested object in an attribute policy (Aux: never matches), the literals `null`, `true`, `false` in `MessageAttributes` scope (Aux: no match against a String attribute), `anything-but` with an `equals-ignore-case` list, escapes in `wildcard` patterns, the 256 KiB limit, key limits and deep matching for `MessageBody`. |
| `RedrivePolicy`                                                                       | Read, write   | `{"deadLetterTargetArn":"<queue ARN>"}`; only that key (as AWS). A target that does not exist is accepted (as AWS). The dead-letter queue must be a queue of this store. An ARN of another service is `deadLetterTargetArn must be a SQS queue`. The target ARN must have the configured partition and account; its region is not compared, as for an `sqs` endpoint (the AWS region rule for a subscription dead-letter queue is not probed). An SQS queue `RedrivePolicy` rejects a target in another region.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `DeliveryPolicy`, `EffectiveDeliveryPolicy`                                           | Read, write   | `DeliveryPolicy` is validated (known sections and fields) and stored; `{}` is valid (as AWS). | `ConfirmationWasAuthenticated`, `SubscriptionRoleArn`                                 | Not available | Not returned.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

### ConfirmSubscription

| Parameter                   | Handling | Validation / default                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `TopicArn`                  | Accepted | Missing topic gives `InvalidParameter: Invalid token`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

## Behavioural differences

Each item names the code that shows it.

1. **ARN identity comes from configuration.** `queue.partition` (default `aws`), `queue.region` (default `us-east-1`)
   and `queue.account_id` (default `000000000000`) compose topic ARNs and are the partition and account that an SQS
   endpoint or dead-letter ARN must use. A stored topic keeps its ARN; after a change of these values the host logs
   one error at startup for stored topics with another identity
   ([service_host.rs](../crates/storage-api/src/service_host.rs)). SQS queue ARNs take the same configured
   partition, region and account ([queue_arn.rs](../crates/queue-provider/src/queue_arn.rs)); `Subscribe` accepts a queue
   ARN of another region (AWS probe) but that delivery cannot find the queue (note 9).
2. **Subscribe to SQS uses the queue ARN**, as AWS. The delivery resolves the queue by name on the same store.
3. **One attribute rule on create and set paths.** `CreateTopic`, `SetTopicAttributes`, `Subscribe` and
   `SetSubscriptionAttributes` apply each supported attribute in the same way and reject every other name. Nothing is
   accepted and dropped.
4. **Filter policies** are evaluated at materialization ([filter_policy.rs](../crates/pubsub-provider/src/filter_policy.rs)).
5. **Publish is two-phase.** `Publish` writes a durable publish intent with a snapshot of the subscriptions
   ([publication_acceptance.rs](../crates/pubsub-provider/src/publication_acceptance.rs)); the delivery runner of each
   node later turns it into one delivery record per confirmed subscription and then delivers
   ([delivery_runner.rs](../crates/pubsub/src/delivery_runner.rs)). A `Publish` wakes the runner of the node that
   accepted it at once; other nodes find work at their next probe, at most `pubsub.delivery.idle_probe_millis` later
   (default 1 s). An idle runner opens
   only read-only probes. A subscription removed after `Publish`
   still receives that publication (conformance test `given_publish_when_subscription_deleted_before_materialize_then_snapshot_preserved`,
   [pubsub_contract_tests.rs:450](../crates/storage-rewrite-conformance/src/pubsub_contract_tests.rs#L450)).
6. **Pending subscriptions get nothing.** Unconfirmed `http` / `https` subscriptions are skipped at fan-out
   ([publication.rs:64](../crates/pubsub-provider/src/publication.rs#L64)); messages published before confirmation are not replayed.
7. **Delivery retry policy.** A delivery attempt has one of three results: delivered, transient, or permanent
   ([delivery_policy.rs](../crates/pubsub-provider/src/delivery_policy.rs)). HTTP `2xx` is delivered; `429`, `5xx`,
   timeouts and network errors are transient; other statuses (also `3xx`, not probed) are permanent. For `sqs`: a
   missing queue or a message that the queue rejects (size, characters, more than 10 raw attributes) is permanent; a
   store conflict, capacity or availability rejection is transient (a store whose durability failed is not settled). No attempt counter ends a delivery: a transient
   failure is retried with equal jitter in `[d/2, d]`, `d = min(cap, 1 s * 2^(attempts-1))`, until a retry deadline
   that is fixed when the record is written (`retry_deadline`, stored in every record; there is no default for a
   record without it, because SNS has no stored data to migrate): 23 days and a 20 s cap for `sqs`, 1 hour and a
   60 s cap for `http`, `https` and subscription confirmations. AWS documents a longer schedule for SQS and 3
   retries 20 s apart by default for HTTP (not probed). A record that waited past its deadline still gets one
   attempt. There is no deferral: a claim asks a destination only for the records it can attempt at once.
8. **Terminal deliveries.** A delivered record is deleted. A permanent failure, or a transient failure at the
   deadline, moves the notification to the subscription's dead-letter queue when it has a `RedrivePolicy`, in the
   same transaction as the delete of the record; else the notification is dropped. A drop is counted with a reason
   (`permanent_no_dlq`, `deadline_no_dlq`, `dead_letter_missing`, `dead_letter_rejected`, `subscription_deleted`) and
   logged with the subscription ARN and message ID only. The dead-letter message has the form of a normal delivery of
   the subscription: the envelope with no message attributes, or for a raw subscription the raw body with the original
   attributes; no attributes are added (as AWS). A subscription confirmation never moves to a dead-letter queue. An
   unsubscribed subscription drops its pending failures. AWS moved a message about 6 s after its destination queue was
   deleted (probe); the Aux timing depends on the delivery runner.
9. **Ordering and duplicates.** Each node runs at most 64 deliveries at a time (`pubsub.delivery.max_in_flight`) and at most 8 for one destination (`pubsub.delivery.per_destination`)
   (an SQS queue ARN, or the lower-case `scheme://host:port` of an HTTP endpoint); a record is claimed only when a
   slot is free, and a record is attempted only while its 30 s lease still covers the 10 s request timeout and 5 s
   for the settle. After 5 consecutive transient failures a destination's circuit breaker opens on that node for
   5 s (+-20% jitter), doubling to 300 s; one probe delivery tests it, and a record past its retry deadline is
   claimed and attempted anyway. A claim asks each destination only for its free slots, so a busy destination or an
   open or half-open breaker leaves the record unclaimed and due; nothing is written for it
   ([delivery_scheduler.rs](../crates/pubsub/src/delivery_scheduler.rs)). After a failure in the current window a
   destination is not refilled until its records in flight end. Deliveries to an `sqs` queue of this store
   are not limited per destination and have no breaker: all records of one claim for one queue (at most 32 records
   and 1 MiB) are enqueued in one transaction; a record whose lease no longer covers the attempt is left to lease expiry. A custom sender that does not answer ends at the request timeout as a transient failure.
   An `sqs` endpoint or dead-letter target in another region is not this store's queue: the delivery is a
   permanent `DestinationMissing` (or the dead-letter queue is missing). A stored row that cannot be decoded is
   counted (`pubsub.delivery.poison`, `pubsub.publish.poison`), logged by key, and moved one hour ahead.
   Known limits: the breaker key is `scheme://host:port` (one host with many paths shares one breaker); a process
   pause longer than the lease can still give a concurrent duplicate over HTTP (at least once). There is no ordering guarantee between messages. A claim lease of 30 seconds
   (`pubsub.delivery.lease_seconds`) recovers records from a dead node, so an HTTP delivery can repeat (no named
   conformance test covers lease expiry; not verified by this assessment). An SQS delivery on the same store is enqueued and settled
   in one transaction under the claim fence, so it repeats only after a crash loses that commit.
10. **Delivery metrics.** `pubsub.delivery.oldest_due_age_ms` and `pubsub.publish.oldest_intent_age_ms` (gauges from
    each probe), `pubsub.delivery.outcome{outcome, reason}`, `pubsub.delivery.in_flight`,
    `pubsub.delivery.breaker_open`, and the provider counter `storage_provider_stage_total{operation="pubsub", stage="delivery_claim_contention_empty"}`. Recommended alarms: warn when the
    oldest due age stays above 60 s for 5 minutes; page above 15 minutes or on any `dropped` outcome. `Publish` has
    no backpressure (owner decision O5).
11. **`DeleteTopic` and `Unsubscribe` are idempotent** ([topic_operations.rs:154](../crates/pubsub-provider/src/topic_operations.rs#L154),
    [subscription_operations.rs:273](../crates/pubsub-provider/src/subscription_operations.rs#L273)).
12. **Message ids are UUID v7** with hyphens ([newtypes.rs:107](../crates/pubsub-provider/src/newtypes.rs#L107)), the AWS format. SQS `MessageId` has the same hyphenated UUID form.
13. **Message size limit is 256 KiB** of message plus attributes, fixed in code
    ([constants.rs:85](../crates/pubsub-provider/src/constants.rs#L85)). AWS limits are not probed.
14. **No `MessageStructure=json`.** Per-protocol bodies are not possible ([protocol.rs:214](../crates/pubsub/src/protocol.rs#L214)).
15. **Custom sender replaces HTTP delivery.** When a `SubscriptionMessageSender` is configured, every notification for an `http` / `https`
    subscription is delivered through it and the built-in HTTP delivery is not used for it
    ([publication.rs:81](../crates/pubsub-provider/src/publication.rs#L81)); subscription confirmations still use built-in HTTP.
    The sender receives the subscription ARN, message id, destination, message bytes and attributes but not
    the subject or topic ARN ([delivery_transport.rs:331](../crates/pubsub/src/delivery_transport.rs#L331)).
